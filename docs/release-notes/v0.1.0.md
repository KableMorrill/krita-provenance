The first public release of krita-provenance: a Krita plugin that records Krita AI Diffusion
generations as you work, then exports a PNG or JPEG with a signed C2PA manifest and a
plain-language AI-use statement. It's an early release, tested inside Krita on Windows 11.

## What it does

- Starts a provenance log in each document Krita creates or opens, kept inside the .kra.
- Records each result applied from Krita AI Diffusion's history, with its model, seed and
  settings and the layer it landed on.
- **Tools ▸ Scripts ▸ Provenance: Export Signed Image…** saves a PNG or JPEG with a signed C2PA
  manifest built from the log, reads it back to check it, and shows a statement such as "1 AI
  generation observed by this plugin since 19 October 2026 (UTC)." When it can't sign, it saves
  a file named `…-unsigned` and says why.
- **Tools ▸ Scripts ▸ Provenance: Set Up Signing** asks first, then downloads c2pa-python,
  cryptography and cffi, checks each against a pinned SHA-256, and makes a signing certificate
  on your computer.
- **Settings ▸ Dockers ▸ Provenance Log** shows the active document's log.

## Install

1. Download `krita-provenance-0.1.0.zip` below.
2. In Krita 5.3, choose Tools ▸ Scripts ▸ Import Python Plugin from File…, pick the zip, answer
   Yes to enable it, and restart Krita.
3. Run Tools ▸ Scripts ▸ Provenance: Set Up Signing. It downloads about 92 MB on Windows and
   19 MB elsewhere.

Recording generations needs Krita AI Diffusion; 1.53.0 is the version tested.

## Known limits

- Tested inside Krita only on Windows 11 (Krita 5.3.4, Krita AI Diffusion 1.53.0). On macOS and
  Linux the automated tests pass, but the plugin hasn't been tried inside Krita there. Reports
  are welcome: rows 1–16 of `docs/smoke-checklist.md` are a good guide. On a Mac, use Krita
  from krita.org rather than the Mac App Store edition.
- Signing isn't available on Intel Macs or Windows on ARM yet.
- Live painting, upscaling and control-layer results aren't recorded yet, and neither are
  edits to layers.
- A document with an image placed into it exports unsigned, and says why.
- Validators report the signer as unrecognized, because the certificate is made on your
  computer. There are no timestamps yet, so validators show no signing date.

The plugin never claims a work is human-made: it states what it observed and says what it
couldn't see. It is built with AI assistance (Claude), as the README and commit history say.
